## 2. 手本の動画の分析（35分の動画から約50コマを確認）

### 画面の作り

- **背景**：濃い紺のグラデーション。ごく薄い星のような点が散っている。全編同じ背景
- **字幕**：全編に出る。画面下の中央、白の太いゴシック、2行まで、薄い影つき。話した言葉そのまま（「〜なんです」など口語も残す）。1〜2文ごとに切り替わる
- **図の上の見出し**：図の上に小さく1行（「政策金利」「125%ルール」「3つの質問」）
- **顔**：手本には話し手の顔は出ない（この企画では右下にワイプを足す）

### 色の決まり

| 色 | 使いどころ |
|---|---|
| オレンジ（赤寄り） | 不利・負担・借りる側・マイナス |
| 青緑（ティール） | 有利・受け取る側・プラス |
| 金色 | 強調する数字（明朝系の大きな数字「1.25%」「3.0%」）・見出し・枠線 |
| 青みのグレー | 比べる相手・基準・過去の値 |

光の滲み（グロー）を全体に薄くかける。線は細い。

### 図の型（出てきた順に多いもの）

1. **流れ図**：左右に丸いアイコン（線画）、間を光る点の列が流れる。「お金が借りる側から貸す側へ流れる」。同じ図を何度も再登場させ、言葉に合わせてラベルや人物アイコンを足していく（手本の主役の図）
2. **棒グラフ**：2〜3本。オレンジ／グレー／青緑。上に金色の数字、差を括弧で示す（「+5万円以上」）
3. **折れ線**：1本だけ、先端が光る。始点と終点の数字だけを書く。話に合わせて注記（「5年で10倍以上」）が後から出る
4. **階段グラフ**：利上げの推移。間隔を下に書く
5. **プラス・マイナスの棒の並び**：実質賃金。マイナスはオレンジ、プラスは青緑
6. **天秤**：2つを比べる
7. **番号つきの枠**：「3つの質問」「3つの予定」。金色の枠、話している番号だけ明るくする
8. **円グラフ2つ並べ**：構成比の比較
9. **丸2つ＋その間を流れる点**：日本⇔アメリカのお金の移動
10. **記事の画面**：ニュース記事のスクリーンショット、要点に黄色の線、右下に「出典：◯◯（日付）」
11. **写真**：日銀本店・街・書類を見る手元など。暗めに落として字幕を乗せる。全体の約2割

### 動き

- 1つの図を数文にわたって出し続け、話の進みに合わせて**要素を足していく**（ページをめくるより、同じ図が育つ）
- 線は左から引かれる、棒は下から伸びる、数字はふわっと出る。派手な切り替えはしない
- 光る点はゆっくり流れ続ける

## 3. この企画の完成形

- 1920×1080・30fps。音は `1.wav` だけ
- 背景・字幕・図は手本の作りに合わせる
- 右下に顔のワイプ（角丸の四角、約400×400、細い金色の枠）
- 字幕は画面下の中央。ワイプと重ならない幅（約900px）に収める
- 図は「右下のワイプにかからない範囲」に組む。右端に要素を置く図（流れ図など）は、全体を少し左に寄せるか、高さをワイプより上に収める

## 4. 手順

### 4-1. 音と映像を合わせる

1. 両方の音を 8kHz・モノラルに落として抜き出す
2. 冒頭5分どうし・末尾5分どうしで相互相関を取り、ずれを出す
3. 2つが一致すればずれは一定。違えば WAV を `atempo` でわずかに伸縮して合わせる
4. 確認：冒頭・中盤・末尾で口と音のずれが1コマ（33ms）以内

### 4-2. 文字起こしと台本の突き合わせ

1. `faster-whisper`（large-v3、CPU）で WAV を文字起こし。単語ごとの時刻つき
2. 台本の文と突き合わせ、文ごとに開始・終了の時刻を付ける
3. 字幕の文字：台本どおりに読んだところは台本の表記を使う（数字・社名の聞き間違いを防ぐ）。台本から外れて話したところは文字起こしを使い、確認の印を付ける
4. 言い直し・長い間は、この段階では切らない（切るかどうかは後で決める）

### 4-3. 図の設計表（`work/scenes.json`）

台本の1〜数文ごとに1場面。項目は、開始・終了の時刻／見出し／図の型（§2の型）／データ／**要素が足される合図の時刻**（例：「5年で10倍以上」と言った瞬間に注記が出る）。

- 数字は台本と `scenario_draft.md` の `>` 行（出典つき）にあるものだけ。図のために数字を足さない
- 同じ図を数文にわたって育てる（手本の作り）。1場面1図で切り替えすぎない
- 主役の図を1つ決めて、何度も再登場させる（この台本なら「AIの頭脳 → ロボットの体 → 日本の部品企業」のような流れ図が候補）
- 色の決まり（§2）を守る。オレンジ＝負担・下げ、青緑＝追い風・伸び

**ブロックごとに作ってレビューを受ける。**まず①だけ作って見てもらう。

### 4-4. 図の動画を作る（Remotion）

- Node 22 の Remotion（Reactで動画を作る道具）で、§2の型を部品として作る
- 字幕・見出し・背景も同じ中で描く
- 出力：`work/graphics_partN.mp4`（1920×1080・30fps・音なし）

### 4-5. 合成（ffmpeg）

1. 合わせた映像から顔まわりを切り抜き（中央の約900×900）、400×400 に縮めて角丸にする
2. 図の動画の右下に重ねる
3. 音は WAV。音量は -14 LUFS にそろえる
4. 素材が全部そろったら、part1〜N をつないで `出力/完成.mp4`

2. 1本目の冒頭3分で 4-2〜4-5 を通す → 見た目を見てもらう

## 9. 台本の言い直し・言い間違いのカット（11/23 計画）

ユーザー指摘の例：カット確認_part1 の 0:29〜0:30（元 41〜52秒、「AIがロボットの」のあと約11秒の言い淀み）、4:46〜4:50（元 351〜354秒、「空売りしてきた」→言い直して「ことを」）。

### なぜ今までの方法で拾えなかったか
Whisper は同じ言葉の繰り返しを省いて書く。そのため「文字起こしの中で同じ文が2回出る所」を探す方法（retake 検出）では、繰り返しが文字に残らなかった箇所を見落とす。

### 見つけ方（3つ）
1. 文字起こしに2回出る所（済み：retake_part1.json の6か所＋手で1か所）
2. 音の側から：声が出ているのに単語が無い区間（単語の時刻が不自然に長い）→ suspect_part1.json（台本部分で46か所）
3. 2 の候補を前後だけ切り出し、言い淀みを省かない設定で文字起こしし直す（verify_suspects.py）→ 何を言い直したかを文字で確かめる

### 切り方
- 台本と照らして、同じ所を2回以上言っていれば、最後まで言い切った読みを残し、それより前の失敗した読みを切る
- 「えー」「あの」などの言い淀みだけの区間も切る
- 切る位置は声の切れ目に合わせる（単語の途中では切らない）。前後の間は §8 の決まり（文末0.60秒・読点0.40秒・文中0.20秒、間は無音）
- 言い間違えたまま直していない所（台本と違う言葉のまま進んだ所）は切れないので、一覧で知らせるだけにする
- **台本に無くても、意図して話しているアドリブは切らない**（11/23 指示。例「僕が死ぬほど嫌いな取引ですね」）。切るのは「同じ所の言い直しの失敗側」と「言い淀みだけの区間」に限る。迷うものは一覧で『残す候補』に分け、勝手に切らない

### 進め方
1. 候補ごとに「カット後の時刻／言った内容／切る部分／残す部分」の一覧を作って見せる
2. 承認をもらってから retake_part1.json に入れ、align.py → cuts.py → build_timeline.py → preview.py で作り直す
3. 2本目以降は、文字起こしのあと自動で 1〜3 を回し、一覧を最初に見せる
